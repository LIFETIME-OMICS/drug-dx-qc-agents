## 📖 Overview
This project implements a **multi-agent pipeline** using the **Google Agent Development Kit (ADK)** to process already deidentified electronic health records (EHRs), classify medications, summarize drug classes, and evaluate whether diagnoses align with prescribed drugs.  

The pipeline ensures **quality control** by identifying patients with medications that lack corresponding diagnoses in their records. The pipeline can also be used to generate **digital twin patients** with prescribed drug classes and linked diagnoses without exposing medication details and any original data. 

Moreover, the project compares two paradigms: one that mimics how humans use software tools and reason about their outputs, and another that shows what happens when an autonomous agent does the entire task internally. This lets us evaluate whether the transparency and modularity of the pipeline outweigh the speed and adaptability of the autonomous approach.

We use this 100 patient synthetic data for testing:
https://www.kaggle.com/datasets/mexwell/synthetic-al-medical-records/data

## 🧠 Agent Architecture

![Diagram](images/MediQC.png "Architecture overview")

The system runs **2 modular agents** in sequence mimicking human+software drug classification:

1. **drug-identifier**  
   Extracts drug names from `medication.csv` and normalizes spelling forms.  
   Output: File drug_names_extracted.csv generated by agent in agents\drug_identifier.py 

2. **drug-classifier**  
   Maps drugs to ATC hierarchical classes (e.g., bronchodilators, antihypertensives) and to ICD-10 diagnosis (dx).  
   Output: drug_classifications.csv generated by agent in agents\drug_classifier.py 

The system runs **QC Evaluator agent** using 1 prompt to work on the same task as the `drug-identifier+drug-classifier` workflow:   

3. **qc-evaluator**  
   LLM mapping to ICD-10 diagnosis (dx) from `medication.csv` and compares mappings with results from `drug-identifier+drug-classifier` workflow  
   Compares dx against EHR `condition.csv` or `diagnosis.csv` and flags patients with prescriptions lacking corresponding diagnoses.  
   Output: qc_flags_test.csv generated by agent in agents\qc_evaluator.py   

**Run other agents**  

4. **stats-summarizer**  
   Responds to prompts. Summarizes drug usage by patient and class using the results of the 1-2-3 agent pipeline, providing context for diagnosis evaluation.   
   
**Script to run first 2 agents in sequence to create the local ATC database**   
scripts\build_atc_database.py

## 🗄️ ATC Database - Self-Maintaining Hybrid Architecture

This project uses a **hybrid WHO + LLM approach** for drug classification:
- ✅ **Authoritative** - Uses official WHO ATC/DDD Index as primary source
- ✅ **Intelligent** - LLM handles synonyms (acetaminophen → paracetamol)
- ✅ **Self-maintaining** - Auto-builds and updates local cache
- ✅ **Fast** - Instant lookups after first run
- ✅ **Ethical** - Respects WHO website robots.txt (10-second delay)

### How It Works

The `drug_classifier` agent automatically:

1. **Checks local cache** first (`output/atc_database.json`) - instant lookup
2. **Fetches from WHO** if not cached - authoritative ATC codes
3. **Uses LLM for synonyms** if WHO lookup fails - intelligent resolution
4. **LLM fallback** for truly unknown drugs - flagged for verification
5. **Auto-saves results** - builds local database incrementally

**No manual database build required!** Just run the agents.

### Usage

**First Run: 2 agent drug classification pipeline**
```bash
# From an input of a medications csv file (test on short file: medications_synthetic_short_8.csv.csv), 
# it generates:  
# - output/atc_database.json: The ATC database
# - output/drug_names_extracted.csv: Intermediate file from agent 1
# - output/drug_classifications.csv: Final classifications from agent 2
#
# Each new drug: 10-second WHO lookup + auto-save to cache
python scripts/build_atc_database.py --medications data/medications_synthetic_short_8.csv   

```

**Test the QC evaluation:**
```bash
# Use as input the output of the 2 agent pipeline to run the QC evaluation  (via python code orchestration)
python -m pytest tests/test_qc_evaluator_python.py -v -s

# Bypass the 2 agent pipeline. Instead, start with the medications input file to run a QC evaluator agent via a single prompt! 
# It may run for 2-3 minutes on 20 medication rows.
# To limit token usage: Use Batch processing configuration as set in tests\conftest.py
# DEFAULT_BATCH_SIZE = 10
# TEST_ROW_LIMIT = 20  
python -m pytest tests/test_qc_evaluator.py::TestQcEvaluatorAgentOrchestration::test_qc_evaluation_with_batch_processing -v -s


# Review results in:
# tests\tmp\qc_flags_agent_orchestration.csv
```

### Data Sources (Priority Order)

1. **Local Cache**: `output/atc_database.json` (instant, built automatically and reused)
2. **WHO ATC/DDD Index**: https://atcddd.fhi.no/ (authoritative, 10-sec delay)
3. **LLM Synonym Resolution**: Gemini suggests alternatives (acetaminophen → paracetamol)
4. **LLM Fallback**: Gemini classification (flagged with `needs_verification=True`)

### Optional: Pre-build Database

Want to build the entire database upfront?

```bash
python scripts/build_atc_database.py --medications data/medications_synthetic.csv
```

This pre-populates the cache, but **the classifier agent builds it** as needed
